安装

Rivet 通过 npm 分发，需要 Node.js 20.6 或更高版本。

不使用 Node 也没关系 —— 独立二进制包内置了运行时，下载后解压即用，体积约 8MB。
终端安装
# npm（推荐）
$ npm i -g @rivet/cli

# pnpm
$ pnpm add -g @rivet/cli

# Homebrew
$ brew install rivet

验证安装

终端输出
$ rivet --version
rivet v2.4.0 · rust core 1.92 · node 22.11.0

快速开始

两条命令创建项目并启动开发服务器。项目模板会自动识别你的包管理器与目录结构。

终端创建并启动
$ rivet init my-app
◇ 选择模板 … react / vue / svelte / vanilla
◇ 安装依赖 … done in 4.1s

$ cd my-app && rivet dev
✓ 依赖预构建完成 142ms
✓ 模块图已加载 38ms
➜ Local: http://localhost:5173/

目录约定

Rivet 不需要你指定入口文件，它按下面的顺序探测 index.html：

  • 项目根目录下的 index.html
  • src/index.html 或 app/index.html
  • 若都没有，则以 src/main.ts 作为入口，输出单页应用
my-app/目录结构
my-app/
├─ index.html
├─ src/
│  ├─ main.tsx
│  ├─ App.tsx
│  └─ styles.css
├─ package.json
└─ node_modules/

配置参考

绝大多数项目不需要配置文件。当需要覆盖默认行为时，在根目录创建 rivet.config.ts（也支持 .js、.mjs）。

rivet.config.ts完整示例
import { defineConfig } from '@rivet/cli'

export default defineConfig({
  // 显式声明插件；不写则自动探测
  plugins: ['@rivet/plugin-react'],


  // 开发服务器
  server: {
    port: 5173,
    host: true,
    open: true,
  },


  // 生产构建
  build: {
    target: 'es2022',
    outDir: 'dist',
    sourcemap: true,
    minify: 'esbuild',
    chunkSizeWarningLimit: 600,
  },
})

常用配置项

配置项类型默认值说明
pluginsstring[]自动探测显式声明要启用的插件包

server.hostbooleanfalse是否监听 0.0.0.0 以便局域网访问
server.proxyobject—开发环境接口代理，键为路径前缀
build.targetstring'es2020'产物目标语法，可选 es2018 至 esnext
build.outDirstring'dist'产物输出目录，相对于项目根
build.sourcemapboolean | 'inline'false是否生成 sourcemap
build.minify'esbuild' | 'terser' | false'esbuild'压缩器选择，terser 兼容旧浏览器
build.assetsDirstring'assets'静态资源输出子目录

插件系统

插件是一个普通的 npm 包，导出 definePlugin() 的结果即可。安装之后 Rivet 会自动读取并注册，你不需要在配置文件里写 plugins 数组。

终端安装插件
$ rivet add @rivet/plugin-react
✓ 已安装 @rivet/plugin-react@2.4.1
✓ 已写入 package.json

内置插件

  • @rivet/plugin-react —— React 19 / 18，Fast Refresh
  • @rivet/plugin-vue —— Vue 3 SFC 与热更新
  • @rivet/plugin-svelte —— Svelte 5，含 SSR 预设
  • @rivet/plugin-solid —— Solid.js 及其编译期响应式
  • @rivet/plugin-tailwind —— Tailwind v4 直接接入
  • @rivet/plugin-mdx —— MDX 与自定义组件映射
  • @rivet/plugin-swc —— 可选的 SWC 转换后端

插件 API

插件在三个阶段被调用：resolveId（解析模块 id）、load（读取文件内容）、transform（转换源码）。每个钩子都可以是同步函数，也可以返回 Promise。

my-plugin.ts完整示例
import type { Plugin } from '@rivet/cli'

export default definePlugin({
  name: 'my-plugin',

  // 拦截对 .env 的请求，返回虚拟模块
  resolveId(id) {
    if (id === 'virtual:env') return '\0virtual:env'
  },

  // 返回模块内容
  load(id) {
    if (id === '\0virtual:env') {
      return `export default ${JSON.stringify(process.env)}`
    }
  },

  // 在模块图构建后执行一次
  buildStart() {
    console.log('[my-plugin] 模块图已就绪')
  },
})
以 \0 开头的模块 id 属于虚拟模块，不会落盘，也不会进入最终产物。

常见问题

端口被占用怎么办

Rivet 默认会自动顺延到下一个可用端口，并在终端里打印实际地址。如果需要固定端口，用 --port 指定即可。

怎么彻底重置缓存

运行 rivet clean --cache --dist 会同时清空增量缓存与产物目录。升级大版本后如果行为异常，这是第一步。

生产构建报内存溢出

把 build.target 调到 es2018 能减少转译开销；另外 rivet build --minify false 会跳过压缩阶段，方便定位是压缩器还是转译器的问题。

如何接入 CI

CI 里只需要 rivet build 这一步。如果希望复用本地缓存，把 cache.dir 指向一个在 CI 里被缓存的目录即可。
